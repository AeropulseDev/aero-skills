# loop-watch v2 — наблюдатель за GitHub

Версия навыка: 2026-11-11b · Исходник: `aero-skills/loop-watch/SKILL.md` (https://github.com/AeropulseDev/aero-skills). Сверка версии — по правилу `skills-index`.

## Как устроено (Claude в цикле НЕ участвует)
- Планировщик Windows, задача `loop-watch`: каждые 15 минут и при входе в Windows `pythonw watch.py run`. Ставит `setup.cmd` (один раз, владелец двойным кликом).
- Опрос: на репозиторий 2–4 запроса с `since` от прошлого успешного опроса (с запасом 10 мин). Комментарии берутся по всему репозиторию сразу, дубли отсекаются по id GitHub. Компьютер был выключен — следующий запуск дочитывает весь пропуск.
- Новое → `watch.db` (SQLite, полный текст) → одно уведомление на запуск: тост Windows (клик открывает ссылку; при важном тост не исчезает сам), при настройке — Telegram. `inbox.md` пересобирается из базы для чтения глазами.
- Важность без ИИ: 🔴 — упоминание `@me` или автор из `vip`; 🟡 — решения, сроки, просьбы, вопросы, смердженные PR; · — остальное.
- Сбой виден: 401 (токен) — тост сразу; сеть — тост после часа неудач. `status` показывает последний успешный опрос.
- Токен — только в переменной пользователя Windows `GITHUB_TOKEN`. Агент его не видит и ему не нужен.

## Что делает агент
Команды — device_bash в папке навыка, `python3 watch.py …` (сети и токена не требуют; базу агент только читает, отметки «прочитано» идут через `acks.txt` и применяются ближайшим опросом на Windows):
- **«что нового», «что на гите», разбор issue** → `unread` (непрочитанное, важное первым, ≤500 знаков на событие). Полный текст нужного — `show <id>`. Ответить владельцу кратко: кто, где, суть, что от него ждут; ссылки. После разбора — `ack <id …>` (или `ack all`, если владелец так сказал). Перечитывать `inbox.md` целиком не нужно.
- **«loop-watch молчит / не работает»** → `status`. Код 1 или опрос старше 45 мин → смотреть хвост `watch.log`; причины: компьютер спал, нет токена (`setup.cmd`), 401 — токен перевыпустить и снова `setup.cmd`.
- **Добавить issue / метку / репозиторий** → правка `config.yaml` (`issues`, `labels`, новый блок `repos`). Новый репозиторий стартует молча с первого запуска.
- **Дочитать прошлое** → владелец на Windows: `python watch.py backfill ГГГГ-ММ-ДД` (нужна сеть и токен — у агента их нет).

## Что отслеживать: `issues` и `labels` (в блоке репозитория)
Порядок в выдаче: важность, затем issue из `issues`, затем по меткам, затем новые issue (`report_new_issues`), затем коммиты и PR.
- `labels` не указано или `[]` — только issue из `issues`. `["any"]` — все issue репозитория. `["attention!", "bug"]` — ещё и issue с этими метками (без учёта регистра).
- Метка, добавленная к старому issue, сама по себе не событие: событием становятся его следующие комментарии.
- Часовой пояс: `timezone` → `city` латиницей → системный; проверка `watch.py tz`.
- Задача планировщика привязана к папке навыка: перенесли или переименовали папку — снова `setup.cmd`.

## Чего не делать
- Не ставить запланированные задачи Claude и `send_later` для слежения: это тратит токены на каждое пробуждение. Режимы v1 «следи здесь», `follow`, browser-режим удалены.
- Не писать в `watch.db` с агента (в примонтированной папке SQLite даёт disk I/O error) — только `ack` через скрипт.
- Не печатать `config.yaml` и переменные окружения в чат.
- Только чтение: на GitHub ничего не публиковать из этого навыка.
- ФИО физлиц и ИНН ИП маскируются скриптом; в пересказе тоже не раскрывать.
