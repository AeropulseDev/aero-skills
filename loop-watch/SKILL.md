# loop-watch — наблюдатель за GitHub

Команды: на Windows — `python watch.py …`; агент Claude в своей Linux-оболочке на компьютере — `python3 watch.py …`.
Файлы: `watch.py`, `probe.js`, `config.yaml` (личный, из `config.example.yaml`), `state.json` (база), `inbox.md` (выжимки, новые сверху). `config.yaml`, `state.json`, `inbox.md`, `probe.json` — в `.gitignore`. Подробности — `README.md`.

## Режим выбирается сам
- **token** — в `config.yaml` есть `github_token` (или переменная `GITHUB_TOKEN`). `watch.py run`: GitHub REST API, один запрос на репозиторий + комментарии только изменившихся issue; коммиты в ветке (`watch_commits`, `branch`), PR (`watch_prs`). Код выхода: 0 — нового нет, 10 — новое записано в inbox.md, 2 — нет токена.
  Запуск агентом (запланированная задача): device_bash `cd <папка навыка> && python3 watch.py run`; код 10 → прочитать верх inbox.md и прислать одно уведомление до 200 символов; иначе завершить молча.
- **browser** — токена нет (только issue по номерам, без меток, коммитов и PR). Агент со встроенным браузером: `watch.py cfg-js` → на https://github.com/ выполнить JS (строка CFG + текст probe.js) → результат в `probe.json` → `watch.py diff` → по CHANGED/NEW_ISSUE прочитать новое и дописать блоки в начало inbox.md (свои комментарии `me` пропускать).

## Что отслеживать: `issues` и `labels` (в блоке репозитория)
Порядок в inbox.md и в уведомлении: сначала issue из `issues` (номера), потом issue по меткам, потом просто новые issue (`report_new_issues`), потом коммиты и PR.
- `labels` не указано или `[]` — следим только за issue из `issues`.
- `labels: ["any"]` — следим за всеми issue репозитория (любые метки), но номерные сообщаются первыми.
- `labels: ["attention!", "bug"]` — кроме номерных, следим за issue с этими метками (имя без учёта регистра). Новый issue с такой меткой сообщается как новый, новые комментарии в нём — как у номерных.
- Метка, добавленная к старому issue, сама по себе не событие: issue попадает в базу, событием становятся его следующие комментарии.
- Репозиторий, которого ещё нет в `state.json`, первый запуск записывает в базу молча (без потока «новых»).
- Только token-режим; в browser-режиме `labels` игнорируются.

## Правила
- Только чтение: ничего не публиковать и не отвечать на GitHub.
- Новый репозиторий/первый запуск — `watch.py init` (база без сообщений). Внимание: `init` перезаписывает базу всех репозиториев, и накопленное «новое» теряется; для одного нового репозитория достаточно обычного `run`.
- Часовой пояс: `timezone` → `city` латиницей → системный; вне `active_hours` `run` молчит. Проверка: `watch.py tz`.
- Добавить issue — номер в `issues` нужного репозитория (или метку в `labels`); новый репозиторий — новый блок в `repos`.
- «Что нового» в рабочей сессии — прочитать верх inbox.md, разобрать, отвеченное пометить «✅» в заголовке блока. ФИО физлиц и ИНН ИП в выжимках маскировать.
- Запланированная задача привязана к папке навыка: переименование или перенос папки ломает её — задачу пересоздать с новым путём.
