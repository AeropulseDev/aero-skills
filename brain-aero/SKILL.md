# brain-aero

Версия навыка: 2026-11-21 · Исходник: `aero-skills/brain-aero/SKILL.md`

## Быстрый путь: справка через brain

Если пользователь просит узнать/найти что-то «через brain» или задаёт справочный вопрос по Аэропульсу:
1. Не открывать реестры навыков, README реестра проектов, HANDOFFS и код. Другие навыки не загружать.
2. Одним вызовом выполнить из каталога навыка `.venv\Scripts\python.exe brain.py find "<ключевые слова>" -n 5`.
   Если ответа нет — ещё один запрос с другими словами или `--kind manual`. Больше двух запросов не делать.
3. Читать только найденные brain'ом файлы, по 10–15 строк вокруг указанной строки, не более 40 строк суммарно.
4. Ответить коротко со ссылками «файл:строки». Если brain ничего не нашёл — сказать об этом и спросить, искать ли в коде.
Предел: 4 вызова инструментов. Не нужно загружать этот навык через `skill`, если включён пресет `brain-lookup` — его инструкции уже встроены.

`brain.py` строит локальный инкрементальный индекс в SQLite. Базовый поиск использует FTS5/BM25; опциональный режим добавляет векторную таблицу и смешивает cosine similarity с лексическим ранжированием. Карта загружается официальным `pm.load()`, второй парсер карты здесь не используется. `node` показывает связанные правила и индексированные фрагменты. Ответы — указатели на источник и короткий отрывок, не длинные копии документов.

## Источники и приватность

В JSON-конфиге подключаются виды `manual`, `handoff`, `kb`, `map`, `wf`, `issue`, `todo`. Пути источников и базы разрешаются относительно каталога конфигурации. `issue` — только локальная SQLite loop-watch: читаются события `issue` и `comment`, соединение read-only/query-only. `todo` — необязательный UTF-8 файл чек-листа, по одной записи на задачу. Путь и набор источников задаёт пользователь локально; личные данные, тексты закрытых источников и пути к ним нельзя добавлять в открытые файлы или коммиты.

Исходные источники не изменяются. Если настроенный источник временно недоступен, старые фрагменты сохраняются; чтобы удалить источник из индекса, уберите его из конфигурации и запустите `build`. База, пользовательский конфиг, eval-файл и модель — локальные производные файлы, не коммитить.

## Команды

Запускать из каталога `brain-aero`:

```text
python brain.py build [--full] [--verbose] [--config PATH]
python brain.py find QUERY [--kind KIND] [--since YYYY-MM-DD] [-n N] [--config PATH]
python brain.py brief QUERY [-n N] [--config PATH]
python brain.py eval [PATH] [-n N] [--config PATH]
python brain.py stats [--config PATH]
python brain.py check [--config PATH]
python brain.py node ASSET_ID [--config PATH]
```

- `build` индексирует изменившиеся файлы и недостающие векторы; `--full` пересобирает индекс.
- `find` ищет по словам и синонимам, при включённой модели использует локальный гибридный поиск; фильтры по виду и дате остаются доступны. `--since` исключает фрагменты без даты.
- `brief` выдаёт свежие issue и передачи и только открытые задачи из настроенного TODO.
- `node` показывает карточку ресурса, его потоки, связанные правила и найденные фрагменты источников.
- `eval` читает локальный набор `K|source:location|query` / `P|source:location|query`. Для manual/handoff можно уточнить раздел: `manual:file.md#часть заголовка`, `handoff:file.md#часть заголовка`. Строки `# baseline|kind|method|K_hits/total|P_hits/total` задают сравнение.
- `check` проверяет источники, даты, целостность SQLite/FTS, ссылки и покрытие векторами; `stats` показывает размер индекса и векторной таблицы.

## Локальные эмбеддинги (необязательно)

FTS5 работает без сторонних зависимостей. Для semantic rerank используется FastEmbed и CPU-модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (многоязычная, локальная). Она включается только настройкой `embeddings.enabled=true`; при выключенной опции FastEmbed не загружается.

1. Создайте виртуальное окружение и установите необязательную зависимость: `python -m venv .venv`, затем активируйте его и выполните `pip install -r requirements-embeddings.txt`.
2. В локальном `brain.config.json` задайте `embeddings.enabled=true`, модель и `cache_dir` (по умолчанию `.venv/model-cache`).
3. `allow_model_download=false` — безопасный режим по умолчанию: веса должны уже быть в локальном кэше. Только для первоначальной загрузки явно переключите его в `true`, запустите `build`, затем верните `false` и пересоберите индекс. Загружаются только файлы модели; тексты документов не отправляются наружу. Векторизация и поиск выполняются локально, внешнего inference API нет.

Векторы хранятся отдельно от FTS в производной таблице SQLite. Изменение источника удаляет его старые векторы в той же транзакции, а `check` показывает повреждённые/отсутствующие записи. Каталог `.venv/model-cache`, база и локальная конфигурация исключены из коммитов.

Для `manual` и `handoff` в гибридный список попадает только ближайший смысловой фрагмент этого вида (`embeddings.semantic_pool`, по умолчанию 1). Остальные места занимает лексический поиск. Карта и остальные виды используют общий пул кандидатов: у коротких узлов перефразировка часто не является самым близким соседом. Вес карты остаётся общим `semantic_weight` (рабочий диапазон 1–2).

Скопируйте `brain.config.example.json` в игнорируемый `brain.config.json`, поправьте пути и при необходимости добавьте локальные источники. После добавления или изменения передачи запускайте `build`; для проверки используйте `check`, `stats` и нужный запрос `find`/`brief`.
